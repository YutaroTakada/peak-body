# Peak Body MVP スコープ

## 1. MVP定義
MVPは、1人のユーザーが1台のiPhoneで筋トレ、食事・栄養、体重を手入力し、端末内へ保存し、選択した1日の記録一覧と直近7日・30日・90日の主要指標を統合ダッシュボードで振り返れる状態とする。

MVPの価値仮説は「複数アプリを行き来せず、日々の入力と身体変化の確認を1つのアプリで完結できれば、記録と振り返りを継続しやすくなる」である。

## 2. MVP完了条件
- Must項目が実装され、対応する受け入れ条件を満たしている。
- 筋トレ、食事、体重の登録・一覧・編集・削除がオフラインで動作する。
- 保存した記録がアプリ再起動後も保持される。
- ダッシュボードの集計が原始記録と一致し、記録の編集・削除後も更新される。
- データ0件、未入力、範囲外入力、保存失敗の主要状態が扱われる。
- VoiceOver、Dynamic Type、色に依存しない表示の基本確認が完了している。

## 3. MoSCoW優先度

### Must — MVPリリースに必須

#### 共通
- iOS 17以上のSwiftUIアプリ。
- 1端末・1ユーザー向けの端末内永続化。
- オフラインでの全主要機能利用。
- 4領域（ホーム、筋トレ、食事、体重）への明確なナビゲーション。
- ホームで選択した1日の体重、食事内容、トレーニング実績をまとめて表示。
- ホームから各記録を1操作で入力開始。
- 設定画面で表示言語を日本語または英語へ切り替え。
- 画面左下の歯車アイコンから設定画面を表示。
- ニュートラル系でライト／ダーク両対応の共通ブランドテーマ（`docs/design/design-spec.md` のデザイントークン。2026-11-09 ユーザー承認で黒基調＋ネオンから変更）。
- 起動直後に06案ベースの短時間スプラッシュを表示。
- 各記録の追加、一覧、詳細、編集、削除。
- 削除前の確認。
- 必須入力、数値範囲、文字数の検証とエラー表示。
- 記録0件の空状態と追加導線。
- 保存失敗時のエラー表示と入力値保持。
- 未保存変更がある入力画面から離脱する際の確認。
- 対象日時、作成日時、更新日時、一意なIDの保持。

#### 筋トレ
- セッション日時、1件以上の種目、1件以上のセットの登録。
- 内蔵種目候補とカスタム種目名。
- 計測方式: 重量×回数、回数のみ、時間。
- セットの追加・削除。
- 新規セットへの直前セット値の複製。
- 入力中の総セット数・総ボリューム表示。
- セッション一覧と詳細。
- 総セット数と、重量を持つセットの総ボリューム算出。
- 任意メモ。

#### 食事・栄養
- 食事日時と食事区分の登録。
- 1食に1件以上の食品項目を登録。
- 食品名とカロリーの必須入力。
- タンパク質、脂質、炭水化物の任意入力。
- 食品項目の追加・削除。
- 入力中の食事合計表示。
- 食事単位および日単位のカロリー・PFC合計。
- 食事一覧と詳細。
- 任意メモ。

#### 体重
- 計測日時と体重（kg）の登録。
- 同日複数件の保持。
- 体重一覧。
- 日次グラフでは同日の最新値を採用。
- 任意メモ。

#### 統合ダッシュボード
- 当日を初期値とする1日単位の日付切り替え。
- 選択日の筋トレセッション数・種目数・総セット数・総ボリュームと実施内容。
- 選択日の総カロリー・PFCと食事・食品内容。
- 選択日の全体重記録と日次代表値。
- 各領域の未記録状態と直接追加導線。
- 共通期間切り替え: 7日、30日、90日。
- 独立した4グラフ:
- 日次代表体重
- 日次摂取カロリー
- 日次タンパク質
- 日次筋トレ総ボリューム（kg・回）
- 指標名、単位、期間、軸ラベル、実測点の表示。
- データ点の日付・値の確認。
- 体重の欠損日と、その他指標の0日の適切な区別。
- データがないグラフの未記録状態と追加導線。

#### 非機能
- 通常利用想定データ量で主要画面を原則1秒以内に表示。
- VoiceOver向けの主要ラベルとグラフ値の読み上げ。
- Dynamic Type対応。
- 色だけに依存しない状態・指標表現。
- 表示文言を共通のローカライズ定義へ集約し、将来言語追加時の修正範囲を限定。
- ユーザーデータを外部送信しない。
- ユーザーデータをログへ平文出力しない。

### Should — MVP後の早期改善、余力があればMVPへ
- 過去に使ったカスタム種目名の再利用候補。
- 最近登録した食品名と栄養値の再利用候補。
- ダッシュボードで前期間との差分を表示。
- グラフ上の選択日を全グラフで連動。
- 記録一覧の日付ジャンプまたは簡易期間絞り込み。
- 軽微な触覚フィードバック。
- アプリ内の免責・データ保存方針の説明画面。
- HealthKit読み取りによる、選択日の運動時間、アクティブエネルギー、睡眠時間のホーム参考表示。

### Could — 将来候補
- ユーザーごとのカロリー、PFC、体重、トレーニング目標。
- 週間・月間の達成率とストリーク。
- 種目別の重量、推定1RM、自己ベスト推移。
- 有酸素運動、歩数、睡眠、体脂肪率などの追加指標。
- 睡眠ステージ分析、睡眠スコア、回復指標の推定。
- 食事テンプレート、レシピ、食事コピー。
- ワークアウトメニュー・テンプレート。
- 写真添付。
- CSV / JSONの書き出し・取り込み。
- iCloudバックアップ。
- ホーム画面ウィジェット。
- 通知・リマインダー。
- ~~ダークモード向けの専用調整。~~ → 2026-11-09 ライト／ダーク両対応をMustへ移動（ユーザー承認）。

### Won't — 今回のMVPでは実施しない
- アカウント作成、ログイン、プロフィール管理。
- バックエンドAPI、クラウドデータベース、複数端末同期。
- SNS、ランキング、友人共有、トレーナーとの共同管理。
- 食品データベース検索、バーコード読み取り、レシート・画像解析。
- HealthKitへの書き込み、Apple Watch専用体験、他社ウェアラブル連携。
- HealthKitデータから筋トレセッションを自動生成する機能。
- AIによるメニュー提案、栄養提案、自動入力、コーチング。
- 医療診断、治療提案、疾患管理、服薬管理。
- lb、oz、kJなどkg / kcal / g以外の単位。
- Web、Android、iPad専用UI。
- サブスクリプション、課金、広告。
- 位置情報。
- なめらかな曲線による未計測値の推定・補間。
- データ共有、公開リンク、PDFレポート。

## 4. リリース分割案

### Increment 1: 記録基盤
- 共通データモデルと端末内永続化。
- 4領域のナビゲーション。
- 体重のCRUD。
- 共通の入力検証、空状態、削除確認。

### Increment 2: 筋トレ
- セッション、種目、セットのCRUD。
- 3種類の計測方式。
- セッション詳細と総ボリューム。

### Increment 3: 食事
- 食事、食品項目のCRUD。
- 食事単位・日単位のカロリーとPFC集計。

### Increment 4: ダッシュボード
- 当日サマリー。
- 7日 / 30日 / 90日の共通期間切り替え。
- 4種類のグラフとアクセシビリティ。
- 編集・削除後の再集計確認。

### Increment 5: 品質確認
- 通常利用想定データ量での性能確認。
- オフライン・再起動・タイムゾーン変更の確認。
- VoiceOver、Dynamic Type、エラー・境界条件の確認。

## 5. 担当別の次工程

### design
- 4領域のナビゲーションと画面遷移を定義する。
- 筋トレの種目・セット、食事の食品項目を素早く追加できる入力UIを設計する。
- 数値入力、エラー、空状態、削除確認、保存失敗の各状態を仕様化する。
- 4グラフを異なる単位で独立表示し、実測点・欠損・0・未記録を区別する。
- Dynamic TypeとVoiceOverを前提に情報階層、色、ラベルを定義する。

### backend
- MVPでバックエンド実装は不要。
- 将来同期の検討時は、`requirements.md` の論理モデルを基に、原始記録を同期するAPI、競合解決、削除伝播、認証を別途設計する。
- MVPのローカルモデルと将来APIモデルを疎結合にできるよう、安定したIDと作成・更新日時を保持する。

### swift / iOS
- SwiftDataを第一候補として、親子関係と削除時の整合性を満たす保存方式を決定する。
- 日次集計をローカルタイムゾーンで実装し、同日最新体重・欠損・0の規則を共通化する。
- Swift Chartsを第一候補として4グラフとVoiceOver用の値表現を実装する。
- 保存失敗、入力途中、再起動、タイムゾーン変更を含むテスト可能な構造にする。

## 7. スコープ変更ルール
- Mustへの追加は、既存Mustの削減またはリリース時期への影響評価とセットで判断する。
- Should / CouldはMustの品質と受け入れ条件を満たした後に着手する。
- Won't項目をMVPへ入れる場合は、プライバシー、バックエンド、運用、審査への影響を再評価する。
- 要確認事項が仮置きから変更された場合は、3要件ファイル間でID、入力範囲、集計規則を同時に更新する。
