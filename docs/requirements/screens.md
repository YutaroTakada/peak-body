# Peak Body MVP 画面別要件

## 1. 目的

本書は、`requirements.md` の機能要件を画面単位へ分解し、デザイン・iOS実装で必要な情報、操作、状態、遷移を定義する。

Peak Bodyの画面設計では、次の順でUXを優先する。

1. 今日の記録状況を1画面で把握できる。
2. 日常的な入力を少ない操作と少ない必須項目で完了できる。
3. 入力後の結果がその場で確認できる。
4. 過去の詳細と長期推移へ迷わず移動できる。

## 2. 画面構成

### 2.1 主ナビゲーション

MVPの主ナビゲーションは、以下の4タブを仮置きする。

| タブ | 初期画面 | 主な目的 |
|---|---|---|
| ホーム | SCR-01 1日一覧 | 選択日の体重・食事・トレーニングを確認し、記録を始める |
| トレーニング | SCR-10 トレーニング履歴 | セッションの履歴確認と登録 |
| 食事 | SCR-20 食事履歴 | 食事の履歴確認と登録 |
| 体重 | SCR-30 体重履歴 | 体重の履歴・推移確認と登録 |

- 新規記録画面は呼び出し元のタブ上へモーダル表示することを基本とする。
- 保存またはキャンセル後は呼び出し元へ戻る。
- ホームの各記録カードから、該当記録の詳細または新規入力へ直接遷移できる。

> 要確認: 推移グラフをホーム内の下部セクションとするか、独立した「推移」画面とするか。MVPではタブ数を増やさず、ホーム内の「推移を見る」からSCR-02へ遷移する仮置き。

### 2.2 共通クイック追加

- 主要4タブのトップ画面には、常に認識可能な「記録を追加」導線を置く。
- ホームの追加導線では「体重」「食事」「トレーニング」を1回の選択で開始できる。
- 各記録タブの追加導線は、その領域の入力画面を直接開く。
- 入力開始までを、各トップ画面から最大2操作以内とする。
- 追加導線はスクロールにより完全に見失わない配置を基本とする。
- VoiceOverでは「体重を記録」のように操作結果を明示する。

### 2.3 設定入口

- MVPでは、設定画面への入口を歯車アイコンのボタンとして画面左下に配置する。
- 設定入口は共通コンポーネントとして実装し、将来ボタン位置や表示方式を変える場合に各画面の修正が広がらないようにする。
- 設定入口は主要な記録操作を妨げない位置とし、VoiceOverでは「設定」と読み上げる。

## 3. 共通画面要件

### 3.1 入力の基本原則

- 初回表示時は、入力に必要な最小限の項目だけを展開する。
- 日付・時刻は呼び出し元で選択中の日付を引き継ぐ。ホームが今日を表示中の場合は現在日時を初期値とする。
- 数値項目は、項目名、入力値、単位を同時に認識できる。
- 入力欄を移動しやすいキーボード操作と、入力完了の導線を設ける。
- 保存ボタンは、必須項目が有効になるまで無効状態とし、無効理由を入力欄付近で判別できる。
- 保存成功後は入力画面を閉じ、呼び出し元の該当箇所へ即時反映する。
- 保存成功を過度なダイアログで妨げず、軽量な視覚・触覚フィードバックで伝える。
- 未保存の変更がある状態で閉じる場合は、破棄または入力継続を選択できる。

### 3.2 一覧の基本原則

- 日付単位でグループ化し、新しい日付を上に表示する。
- 行全体をタップ可能にし、詳細へ遷移できる。
- 行内の主要情報を省略しすぎず、詳細を開かなくても記録を識別できる。
- スワイプ操作だけに依存せず、詳細画面からも編集・削除できる。
- 空状態では、記録する価値の短い説明と、その領域の追加ボタンを表示する。

### 3.3 共通状態

各画面は必要に応じて、通常、空、対象日未記録、入力エラー、保存失敗、削除確認、Dynamic Type、VoiceOverの各状態を持つ。

## 4. ホーム・振り返り

### SCR-00 スプラッシュ

- アプリ起動直後、ホーム画面を表示する前に短時間表示する。
- 表示内容は参考画像の06案をベースにしたPeak Bodyロゴ、ネオン山型グラフ、黒背景とする。
- 2026-11-09のテーマ変更（FR-8）により、スプラッシュ画像を新方針に合わせて刷新するかは要確認。仮置きとして当面は既存の06案画像を使う。
- 表示後は自動でホームへ遷移し、ユーザー操作を要求しない。
- スプラッシュはブランド演出に留め、記録開始までの待ち時間を過度に増やさない。

### SCR-01 1日一覧（ホーム）

#### 目的

選択した1日の体重、食事内容、トレーニング実績を一続きの画面で確認し、不足している記録をその場から追加する。

#### 初期状態

- 初期選択日は端末ローカル日付の今日とする。
- 画面上部に選択日を表示し、前日・翌日へ1日単位で移動できる。
- 未来日は選択不可とする。
- 今日以外を表示中は「今日へ戻る」操作を提供する。

#### 表示内容

1. 日付ヘッダー
   - 選択日、曜日、今日かどうか
   - 前日、翌日、今日へ戻る操作
2. 体重カード
   - 選択日の全体重記録
   - 複数件ある場合は時刻順で表示し、日次代表値となる最新記録を明示
   - 未記録時は「未記録」と追加ボタンを表示
3. 食事カード
   - 日次合計カロリー、タンパク質、脂質、炭水化物
   - 食事区分・時刻ごとの食事と、食品名、食事合計カロリー
   - 食事ごとの詳細、編集への導線
4. トレーニングカード
   - セッション数、総種目数、総セット数、算出可能な総ボリューム
   - セッションごとの実施時刻、種目名、セット数
   - セッション詳細、編集への導線
5. 推移への導線
   - 「推移を見る」からSCR-02へ遷移
6. HealthKit参考カード（任意）
   - ユーザーが連携を開始した場合のみ、選択日の運動時間、アクティブエネルギー、睡眠時間を参考表示
   - 未連携時は主表示を圧迫しない小さな連携導線に留める
   - 手入力の筋トレ記録とは別データであることを明示

#### 操作要件

- 各カードには領域別の追加ボタンを置き、該当日を引き継いで入力画面を開く。
- 既存記録を選択すると該当詳細を開く。
- 画面全体の共通追加から、3種類の記録を選択できる。
- 保存後は選択日を維持し、追加・変更した記録が見える位置へ戻る。
- 日付変更は水平方向ジェスチャーを採用してよいが、ジェスチャーだけを必須操作にしない。
- HealthKit連携の権限要求は初回表示時には行わず、ユーザーが連携操作を選んだ時に行う。

#### 受け入れ条件

- 1画面の縦スクロール内で、選択日の3領域の記録有無と概要を確認できる。
- 一部が未記録でも、他領域の記録は通常どおり表示される。
- 各記録をカード内の1回の追加操作で入力開始できる。
- 同日に複数の記録がある場合、省略せず各記録へ到達できる。
- 追加・編集・削除後、集計と一覧が即時更新される。
- HealthKitが未許可または未取得でも、体重・食事・トレーニングの表示と入力導線は通常どおり利用できる。

### SCR-02 推移

- 7日、30日、90日の期間切り替えを画面上部に置く。
- 体重、摂取カロリー、タンパク質、トレーニングボリュームを独立したカードで表示する。
- データ点を選択すると日付と値を表示する。
- カードの未記録状態から対応する入力画面を開ける。

## 5. トレーニング

### SCR-10 トレーニング履歴

- 日付ごとにセッションをまとめ、新しい順に表示する。
- 各セッションに時刻、種目名、種目数、総セット数、総ボリュームを表示する。
- 追加ボタンからSCR-12、セッション選択からSCR-11を開く。
- 0件時は、最初のトレーニングを記録する追加導線を表示する。

### SCR-11 トレーニング詳細

- 実施日時、全種目、全セット、総セット数、総ボリューム、メモを表示する。
- 編集でSCR-12を保存済み値入りで開く。
- 削除は対象日時と主要種目が分かる確認を経て実行する。

### SCR-12 トレーニング入力・編集

- 日時、種目1件、種目内のセット1件を初期表示する。
- メモは初期状態で折りたたみ、必要なユーザーだけが展開できる。
- 種目選択では、内蔵候補、最近使用した種目、カスタム種目追加を同じ導線から利用できる。
- セット追加時は直前セットの重量・回数または時間を初期値として複製する。
- 数値入力後に次の入力欄または次セットへ移動できる。
- 画面内で総セット数と総ボリュームを確認できる。
- 種目とセットの追加、削除、並べ替えができる。
- 計測方式に不要な入力欄は表示しない。

## 6. 食事

### SCR-20 食事履歴

- 日付ごとに、日次カロリー・PFC合計と食事一覧を表示する。
- 各食事に食事区分、時刻、食品名、合計カロリーを表示する。
- 追加ボタンからSCR-22、食事選択からSCR-21を開く。

### SCR-21 食事詳細

- 食事日時、食事区分、全食品、食品ごとのカロリー・PFC、食事合計、メモを表示する。
- PFCは、未入力と0入力を判別できる。
- 編集でSCR-22を保存済み値入りで開く。
- 削除は食事区分、日時、主要食品名が分かる確認を経て実行する。

### SCR-22 食事入力・編集

- 食事日時から推定した食事区分を初期選択し、ユーザーが変更できる。
- 食品項目1件を初期表示し、必須入力は食品名とカロリーとする。
- PFCとメモは任意項目として明確に区別し、初期状態では折りたたんでよい。
- 最近入力した食品を候補表示し、栄養値を再利用できることをShould要件とする。
- 入力中に食事全体のカロリー・PFC合計を更新する。
- 食品項目の追加、削除、並べ替えができる。
- カロリーのみでも保存でき、PFC入力を強制しない。

## 7. 体重

### SCR-30 体重履歴

- 直近の体重、前回記録との差、記録日時を上部へ表示する。
- 体重推移グラフと、日時降順の全記録を表示する。
- 同日複数件を省略しない。
- 追加ボタンからSCR-32、記録選択からSCR-31を開く。

> 要確認: 「前回記録との差」は入力結果の実感を高めるためShouldとして仮置き。

### SCR-31 体重詳細

- 計測日時、体重、メモを表示する。
- 編集でSCR-32を保存済み値入りで開く。
- 削除は日時と体重が分かる確認を経て実行する。

### SCR-32 体重入力・編集

- 画面を開いた直後に体重入力欄へフォーカスする。
- 数値キーボードを表示し、単位kgを常時表示する。
- 前回の体重を参考値として表示するが、新規記録値として自動保存しない。
- 日時は現在日時またはホームで選択中の日付を初期値とし、通常は変更操作を要求しない。
- メモは任意項目として折りたたんでよい。
- 通常ケースでは、体重を入力して保存するだけで登録できる。

## 8. 共通補助画面・ダイアログ

### SCR-80 設定

- 表示言語を日本語または英語から選択できる。
- 選択後、画面上の主要文言は選択言語へ切り替わる。
- 設定値は端末内に保存し、アプリ再起動後も維持する。
- ユーザーが入力した食品名、種目名、メモは表示言語変更によって翻訳・変更しない。
- 新しい言語を追加する場合に備え、画面ごとの直書き文言ではなく共通の文言キーで管理する。

### SCR-90 日時選択

- 過去または当日の日時を選択でき、未来日時は確定できない。
- キャンセル時は元の日時を保持する。

### SCR-91 削除確認

- 削除対象の種類、日時、識別に必要な主要情報を表示する。
- 「削除」と「キャンセル」を明確に区別する。

### SCR-92 保存失敗

- 保存できなかったこと、入力が保持されていること、再試行方法を表示する。
- エラー詳細に健康関連の入力内容を含めない。

## 9. UXに関するMVP判断

「入力しやすさ」を満たすため、以下をMVPのMustとする。

- トレーニングの新規セットへ直前セット値を複製する。
- 入力中の食事合計、トレーニング合計を表示する。
- 未保存変更がある入力画面から離脱する際に確認する。
- ニュートラル系でライト／ダーク両対応のブランドテーマを `docs/design/design-spec.md` のデザイントークンとして共通化し、画面ごとの色・余白・角丸の指定を分散させない（2026-11-09 ユーザー承認で黒基調＋ネオンから変更）。

以下は有用だがShouldのままとする。

- 最近使用したカスタム種目の再利用候補。
- 最近入力した食品と栄養値の再利用候補。
- 前回体重との差分表示。
- HealthKit読み取りによる運動時間、アクティブエネルギー、睡眠時間の参考表示。
